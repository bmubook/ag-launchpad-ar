# 🐘 أساس البيانات البديل — Supabase (PostgreSQL)

> هذا المخطط **طبقة بيانات** تحل محل Firebase في أي مخطط آخر: `web.md` أو `react-native.md` أو `flutter.md` أو `backend.md`. الواجهة والتنسيق والجودة تبقى من المخطط الأصلي، وتتغير أقسام قاعدة البيانات والمصادقة والحماية والنشر وفق هذا الملف.
> القواعد هنا مأخوذة من التوثيق الرسمي، ومن 96 ثغرة حقيقية أُغلقت في تطبيق إنتاجي على Supabase. الدروس كاملة في مهارة `.claude/skills/supabase-security/SKILL.md`، ويطبّقها الوكيل تلقائياً عند أي جدول أو سياسة أو دالة.

| منطق الخادم | دوال Postgres المحروسة، أو Edge Functions | ما يمس المال أو الصلاحيات يُنفَّذ في الخادم لا في التطبيق | https://supabase.com/docs/guides/functions |
| الهجرات والتجربة المحلية | Supabase CLI + Docker | كل تغيير ملف SQL مؤرخ، وقاعدة محلية للتجربة | https://supabase.com/docs/guides/local-development |

## 3. سياسة الإصدارات
- المتطلبات: Supabase CLI (أو `npx supabase`، ويحتاج Node.js 20 أو أحدث)، و Docker Desktop (OrbStack أو بديله على الماك). قارنها بنتيجة `/env-audit`.
- لا تثبّت أرقام الإصدارات من هذا الملف. اتبع دليل التثبيت الرسمي الحالي: https://supabase.com/docs/guides/local-development/cli/getting-started

## 4. هيكل المجلدات

```
supabase/
├── config.toml              ← إعدادات القاعدة المحلية والمصادقة (يُنشئه supabase init)
├── migrations/              ← كل تغيير ملف SQL مؤرخ: جداول، RLS، منح، دوال، زنادات
├── tests/database/          ← اختبارات pgTAP: من يُقبل ومن يُرفض لكل جدول ودالة
├── seed.sql                 ← بيانات تجربة للقاعدة المحلية فقط
└── functions/               ← Edge Functions (عند الحاجة)
src/lib/supabase/            ← تهيئة العميل: client للمتصفح، server للخادم
src/services/                ← كل قراءة وكتابة للقاعدة هنا لا داخل الصفحات
```

## 5. خط الأساس الأمني

**المفاتيح:**

| المفتاح | أين يوضع | ملاحظة |
|:---|:---|:---|
| `sb_publishable_...` (أو `anon` القديم) | التطبيق والمتصفح | عام بطبيعته؛ الحماية الحقيقية في RLS |
| `sb_secret_...` (أو `service_role` القديم) | الخادم وحده، من متغير بيئة | يتخطى RLS كلها. لا يُوضع في التطبيق ولا في متغير `NEXT_PUBLIC_` ولا في Git. الحارس وفحص الإطلاق يكشفانه |

**الأسئلة الأربعة لكل جدول أو دالة:** من يستطيع مناداته (افترض أي أحد بالمفتاح العام)؟ من أين تأتي هوية الطالب: من الجلسة أم من معامل يرسله؟ ما الأعمدة التي يغيّرها وبأي قيم؟ هل للفعل باب آخر (عرض View، دالة شقيقة، نسخة قديمة من التطبيق)؟

**القواعد:**
- **كل جدول يولد مغلقاً:** `enable row level security` في هجرة إنشائه، ثم `revoke all ... from anon, authenticated` ومنح ما تحتاجه الشاشات فقط (الكتابة بالأعمدة)، وسياسة لكل عملية (`select` و `insert` و `update` و `delete`) مع الدور صراحةً (`to authenticated`).
- **«مسجّل» ليس «مالكاً»:** البيانات الشخصية تشترط `(select auth.uid()) = user_id`، وعمود السياسة له فهرس.
- **السياسات تُجمع بـ«أو»:** سياسة واحدة شرطها `true` تُبطل كل ما جاورها. افحص مجموع سياسات الجدول.
- **RLS يحرس الصفوف لا الأعمدة:** عمود سري في صف مقروء يحتاج منح أعمدة، وعمود الصلاحية (`is_admin`، الحالة، الرصيد) لا يعدّله صاحب الصف؛ يحرسه زناد بقائمة سماح على الإدراج والتعديل معاً.
- **لا صلاحية من `user_metadata`:** يعدّله المستخدم بنفسه. الصلاحيات في جدول محروس أو `app_metadata`.
- **العروض (Views) تتخطى RLS:** أنشئها بـ `with (security_invoker = true)`.
- **دوال `security definer`:** في مخطط خاص غير مكشوف، مع `set search_path = ''`، والهوية من `auth.uid()` لا من معامل مع رفض صريح إذا كانت NULL (الزائر)، و `revoke all on function ... from public, anon` ثم منح `authenticated` حيث يلزم.
- **الملفات (Storage):** الحاوية خاصة افتراضياً، وسياسات `storage.objects` لكل عملية في هجرة، والمسار يبدأ بمعرّف صاحبه: `(storage.foldername(name))[1] = (select auth.uid())::text`. الحاوية العامة لما يراه الجميع عمداً فقط، ولا يكتب فيها إلا صاحب المجلد.
- **المال والنقاط:** لا يكتبها التطبيق أبداً؛ تتحرك بدالة محروسة في معاملة واحدة تقفل الصف (`select ... for update`)، والوقت يختمه الخادم.
- **كل نداء مكلف** (ذكاء اصطناعي، بريد، رسائل) من الخادم لمستخدم موثّق مع حد لكل مستخدم.
- **لا تعديل من لوحة التحكم دون هجرة:** ما يُغيَّر في اللوحة يُلتقط بـ `supabase db diff` إلى هجرة في اليوم نفسه، وإلا أعاد بناء من المستودع الثغرات.

## 6. خط أساس الجودة (ما ينفّذه `/quality-setup`)
| الأداة | الاختيار |
|:---|:---|
| القاعدة المحلية | `supabase init` ثم `supabase start` (Docker) |
| اختبارات الحماية | `supabase/tests/database/*.sql` بـ pgTAP بالنموذج في `.claude/skills/db-change/supabase.md`: الزائر والغريب يُرفضان في كل عملية، والمالك يعمل، والأعمدة المحروسة لا تتغير، و RLS على كل جداول `public` |
| تشغيلها | بوابة الإثبات تكتشف `supabase/tests` وتشغّل `supabase db reset --local && supabase test db --local` على **القاعدة المحلية فقط** كلما تغيّرت هجرة أو اختبار |
| فحص المخطط | `supabase db lint` محلياً |
| CI | خطوة `supabase/setup-cli` ثم `supabase start` و `supabase test db` على المشغّل |
| بقية الأدوات | من المخطط الأصلي (ESLint و Vitest للويب، إلخ) |

> ⛔ **قاعدة اختبار منفصلة إلزامياً:** الاختبارات وسكربتات التجربة والتنظيف تعمل على القاعدة المحلية وحدها. لا `--linked` ولا `--db-url` لقاعدة الإنتاج في أي اختبار أو سكربت.

## 7. النشر
1. أنشئ المشروع من https://supabase.com/dashboard ، ثم `supabase login` و `supabase link --project-ref <معرّف المشروع>`.
2. بعد نجاح الاختبارات المحلية وموافقتك: `supabase db push`.
3. افتح **Security Advisor** و **Performance Advisor** في لوحة التحكم بعد كل نشر يمس الصلاحيات، وأصلح كل تنبيه بهجرة جديدة (🔍 تحقق بنفسك).
4. إعدادات المصادقة في اللوحة: رابط الموقع الحي لا `localhost`، وقائمة روابط التحويل، ورفض كلمات المرور المسرّبة.
5. انقل المفاتيح إلى `sb_publishable_` و `sb_secret_`؛ Supabase تخطط لإيقاف `anon` و `service_role` القديمة. ومفتاح سري منفصل لكل خدمة خلفية.
6. خطة Pro تحتاج تفعيل حد الإنفاق (Spend Cap) أو تنبيه ميزانية.

## 8. أخطاء المبتدئين الشائعة وكيف يمنعها المخطط
| الخطأ | الوقاية |
|:---|:---|
| جدول بلا RLS فيقرؤه أي أحد بالمفتاح العام | RLS في هجرة الإنشاء + اختبار يفحص `pg_tables` + مُراجع الأمن |
| حاوية ملفات عامة أو بشرط `bucket_id` وحده فيقرأ الجميع ملفات الجميع | حاوية خاصة + شرط مجلد المالك في كل سياسة |
| مفتاح `service_role` في التطبيق | الحارس يمنع كتابته، و `release-check.mjs` يكشفه في ملفات البناء |
| سياسة `using (true)` «مؤقتة» للتجربة | اختبار الغريب والزائر يفشل فوراً |
| التعديل من اللوحة فيختلف الإنتاج عن المستودع | `/db-change` و `supabase db diff` |
| تشغيل سكربت تجربة على الإنتاج | القاعدة المحلية فقط، والنشر بموافقة |
| المستخدم يرفع رصيده أو يجعل نفسه مشرفاً | الأعمدة الحساسة محروسة بزناد، والمال بدوال محروسة |
