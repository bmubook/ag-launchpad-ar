# 📖 قاموس المصطلحات التقنية

قاموس عربي مبسّط للمصطلحات التي ستقابلها أثناء بناء مشروعك. في **وضع التعلّم** يضيف الوكيل إليه تلقائياً كل مصطلح جديد مهم يظهر في مشروعك، ويمكنك طلب شرح أي مصطلح بالأمر `/explain <المصطلح>` في Claude Code.

> الترتيب أبجدي حسب المصطلح العربي. الشرح في 15 كلمة كحد أقصى.

| المصطلح | English | الشرح المبسّط | مثال |
| :--- | :--- | :--- | :--- |
| اتجاه من اليمين لليسار | RTL (Right-to-Left) | عرض الصفحة بالاتجاه المناسب للعربية مع ترتيب صحيح للعناصر | `dir="rtl"` في وسم `<html>` |
| اختبار | Test | كود يتحقق آلياً أن جزءاً من التطبيق يعمل كما يجب | اختبار يتأكد أن مجموع السلة صحيح |
| اختبار الوحدة | Unit Test | اختبار لدالة واحدة صغيرة بمعزل عن باقي التطبيق | اختبار دالة حساب الضريبة |
| استرجاع | Rollback | العودة إلى آخر نسخة مستقرة بعد تعديل فاشل | `git revert` لآخر تعديل |
| استضافة | Hosting | خادم على الإنترنت يشغّل تطبيقك ليصل إليه الناس | Vercel أو Netlify |
| إطار عمل | Framework | هيكل جاهز يحدد طريقة بناء التطبيق ويوفر أدوات كثيرة | Next.js أو Flutter |
| إطلاق / نشر | Deploy | رفع نسخة من التطبيق على الاستضافة ليستخدمها الناس | نشر الموقع على Vercel |
| إعادة هيكلة | Refactor | تحسين تنظيم الكود دون تغيير ما يفعله | تقسيم ملف كبير إلى ملفات صغيرة |
| انحدار | Regression | عودة خطأ قديم أو تعطل ميزة كانت تعمل بعد تعديل جديد | زر الدفع توقف بعد تعديل التصميم |
| إيداع | Commit | لقطة محفوظة من تعديلاتك في Git مع وصف مختصر | `feat(cart): إضافة السلة` |
| بناء | Build | تحويل الكود إلى نسخة جاهزة للتشغيل والنشر | `npm run build` |
| بيئة العزل | Sandbox | مكان آمن لتجربة الكود دون المساس بالنسخة المستقرة | فرع Git مؤقت مع تشغيل الاختبارات |
| تبعية / حزمة | Dependency / Package | مكتبة جاهزة يعتمد عليها مشروعك ويثبّتها مدير الحزم | `zod` داخل `package.json` |
| تجاوب | Responsive | تصميم يتكيف تلقائياً مع مقاس الجوال والآيباد والكمبيوتر | القائمة تصبح زراً على الجوال |
| تحليل السبب الجذري | Root Cause Analysis | البحث عن السبب الحقيقي للخطأ لا عن عَرَضه الظاهر | الصفحة بيضاء لأن متغيراً بيئياً مفقود |
| تخزين مؤقت | Cache | حفظ نتيجة مؤقتاً لتسريع الطلبات التالية | الصور تظهر أسرع في الزيارة الثانية |
| تدقيق الكود | Linter | أداة تكشف الأخطاء والممارسات السيئة قبل تشغيل الكود | ESLint أو `flutter analyze` |
| ترحيل / هجرة | Migration | ملف مؤرخ يسجّل تعديلاً على هيكل قاعدة البيانات | ملف يضيف جدول الطلبات |
| تعدد اللغات | i18n | تجهيز التطبيق ليدعم أكثر من لغة دون تعديل الكود | `locales/ar.json` و `locales/en.json` |
| تفويض / صلاحيات | Authorization | تحديد ما يُسمح للمستخدم بفعله بعد تسجيل دخوله | المدير فقط يحذف المنتجات |
| توكن / رمز دخول | Token | رمز رقمي يثبت هوية المستخدم في كل طلب | رمز الجلسة بعد تسجيل الدخول |
| ثغرة | Vulnerability | ضعف في الكود يسمح لمهاجم بالوصول إلى ما لا يحق له | كلمة مرور مكتوبة داخل الكود |
| جدول | Table | مجموعة بيانات من نوع واحد في قاعدة البيانات، صفوف وأعمدة | جدول المستخدمين |
| حالة | State | بيانات تتغير أثناء الاستخدام وتتحكم فيما يظهر على الشاشة | عدد المنتجات في السلة |
| حقن الأوامر النصية | Prompt Injection | نص خبيث يحاول خداع الوكيل لتنفيذ أوامر لم تطلبها | ملف مستورد يطلب تجاهل التعليمات |
| خادم / واجهة خلفية | Backend | الجزء الذي يعمل على الخادم ويعالج البيانات والمنطق | حفظ الطلب في قاعدة البيانات |
| خطأ برمجي | Bug | سلوك غير متوقع في التطبيق يحتاج إصلاحاً | الزر لا يستجيب عند الضغط |
| دمج | Merge | ضم تعديلات فرع إلى فرع آخر | دمج فرع الميزة في `main` |
| رمز JWT | JWT (JSON Web Token) | توكن موقّع يحمل معلومات المستخدم ويتحقق منه الخادم | توكن جلسة Supabase |
| سياسات أمان الصفوف | RLS (Row Level Security) | قواعد في قاعدة البيانات تمنع المستخدم من رؤية بيانات غيره | كل عميل يرى طلباته فقط |
| شهادة الأمان | HTTPS | اتصال مشفّر بين المتصفح والخادم يحمي البيانات | القفل بجانب رابط الموقع |
| فحص آلي مستمر | CI (Continuous Integration) | تشغيل الاختبارات تلقائياً على GitHub مع كل رفع للكود | GitHub Actions |
| فرع | Branch | نسخة موازية من الكود لتجربة تعديل دون المساس بالأصل | `fix/login-error` |
| قاعدة بيانات | Database | المكان المنظم الذي تُحفظ فيه بيانات التطبيق بشكل دائم | PostgreSQL في Supabase |
| متغيرات البيئة | Environment Variables (`.env`) | قيم سرية أو إعدادات تُحفظ خارج الكود | مفتاح قاعدة البيانات في `.env` |
| مستودع | Repository | مجلد المشروع مع كامل تاريخ تعديلاته في Git | مستودعك على GitHub |
| مصادقة | Authentication | التحقق من هوية المستخدم عند تسجيل الدخول | الدخول بالبريد وكلمة المرور |
| مفتاح سري | Secret Key | قيمة تمنح صلاحيات واسعة ولا يجوز أن تظهر في الكود | مفتاح `service_role` في Supabase |
| مكتبة | Library | كود جاهز لمهمة محددة تستدعيه عند الحاجة | `date-fns` لمعالجة التواريخ |
| مكوّن | Component | قطعة واجهة مستقلة قابلة لإعادة الاستخدام | زر أو بطاقة منتج |
| ملف القفل | Lockfile | ملف يثبّت الإصدارات الدقيقة للحزم ليعمل المشروع بالطريقة نفسها | `package-lock.json` |
| منسّق الكود | Formatter | أداة ترتّب شكل الكود تلقائياً بأسلوب موحّد | Prettier أو `dart format` |
| مهارة | Skill (Claude Code) | تعليمات جاهزة تُستدعى بأمر يبدأ بـ `/` | `/next` |
| نطاق | Domain | اسم موقعك على الإنترنت | `rahu.store` |
| نقطة اتصال برمجية | API | طريقة منظمة يتبادل بها تطبيقان البيانات | طلب قائمة المنتجات من الخادم |
| نموذج أولي قابل للإطلاق | MVP (Minimum Viable Product) | أصغر نسخة من المنتج تحل المشكلة الأساسية للمستخدم | متجر فيه عرض وسلة ودفع فقط |
| هوك في Claude Code | Hook (Claude Code) | سكربت يعمل تلقائياً عند أحداث معينة في Claude Code | منع قراءة ملف `.env` |
| هوك في React | Hook (React) | دالة تبدأ بـ `use` تضيف حالة أو سلوكاً للمكوّن | `useState` |
| واجهة أمامية | Frontend | الجزء الذي يراه المستخدم ويتفاعل معه | صفحة المتجر |
| وصولية | Accessibility | جعل التطبيق قابلاً للاستخدام لذوي الإعاقة | قارئ الشاشة يقرأ أسماء الأزرار |
| وكيل فرعي | Subagent | وكيل ذكاء اصطناعي مستقل يُكلَّف بمهمة محددة ثم يعيد تقريره | مُراجع الأمن في `/consensus-gate` |
