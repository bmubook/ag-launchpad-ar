# &rlm;/env-audit — الفحص البيئي

> البند 10 — `rules_workflow.md`: الكود يُكتب متوافقاً 100% مع الإصدارات المثبتة على جهاز المستخدم، ولا تُطلب ترقية أي أداة إلا إذا تعذّر التنفيذ بدونها، وبعد موافقة صريحة.

افتتح الرد باسم النداء، ولا تستخدم وسم `<div dir="rtl">` في المحادثة.

## الخطوة 1 — تشغيل السكربت

1. شغّل بأداة Bash من جذر المشروع: `node .claude/scripts/env-audit.mjs`
   (إن لم تتوفر أداة Bash — Windows بلا Git Bash — فاستخدم أداة PowerShell بالأمر نفسه، واعتبر ذلك دليلاً على غياب Git Bash في الخطوة 5.)
2. عند الفشل:

   | العَرَض | السبب | الإجراء |
   |:--|:--|:--|
   | `node: command not found` أو `is not recognized` | Node.js غير مثبت | Node.js 18+ متطلب أساسي للقالب؛ بدونه لا تعمل الـ Hooks ولا شريط الحالة ولا السكربتات. اطلب من المستخدم تثبيت إصدار LTS من https://nodejs.org ثم إعادة تشغيل Claude Code، وتابع بالأوامر البديلة. |
   | `Cannot find module` | السكربت مفقود | ملفات القالب ناقصة؛ تابع بالأوامر البديلة. |
   | خطأ آخر | — | اعرض رسالة الخطأ كما هي، وتابع بالأوامر البديلة. |

3. الأوامر البديلة (كل أمر منفرداً، و"غير مثبت" لما يفشل): `node -v`، `npm -v`، `git --version`، `python --version`، `flutter --version`، `dart --version`، `firebase --version`، `java -version`، و`uname -a` (أو `[System.Environment]::OSVersion.VersionString` في PowerShell). المنافذ في هذه الحالة: `لم تُفحص`.

## الخطوة 2 — عرض النتيجة

1. اعرض مخرجات السكربت كما هي (Markdown جاهز).
2. أتبعها بقسم `### الخلاصة` من 3–5 نقاط: نظام التشغيل، Node، Git، Git Bash، المنافذ المشغولة 🔴.

## الخطوة 3 — تحديث القسم 6 في `project_map.md`

1. اقرأ `project_map.md`. إذا كانت نتائج الفحص مطابقة لما في القسم 6 فلا تعدّل الملف.
2. غير ذلك: استبدل **منطقة البيئة** — من سطر `* **نظام التشغيل المكتشف:**` حتى آخر سطر قبل `* **المهارات المستوردة النشطة` — بما يلي بالترتيب:
   * مخرجات السكربت كما هي (إذا بدأت بسطر عنوان `#` فلا تنسخه).
   * سطر فارغ، ثم: `* **البيئة النشطة محلياً:** بيئة التطوير المحلية (Local Development)`
3. أبقِ ما عدا ذلك كما هو حرفياً: سطر الملاحظة `>`، وسطر `* **المهارات المستوردة النشطة`، وسطر المرساة `* **وضع التشغيل النشط:**` بقيمته الحالية، ووسمَي `<div dir="rtl">` و `</div>`.

## الخطوة 4 — المقارنة مع الـ Tech Stack

0. **متطلب القالب نفسه (بصرف النظر عن الـ Stack):** إذا كان إصدار Node.js أقدم من 18 فنبّه بـ `⚠️` أن الـ Hooks والسكربتات وشريط الحالة تتطلب 18+، واطلب من المستخدم تثبيت إصدار LTS؛ هذه ترقية لا بديل لها (البند 10).
1. إذا كان جدول القسم 5 ما زال `[لم يُحدد بعد]`: اكتب سطراً واحداً: "المقارنة مع الـ Stack تتم بعد اعتماده في `/grill-me`"، وانتقل إلى الخطوة 5.
2. غير ذلك: حدّد الأدوات المطلوبة:

   | التقنية في القسم 5 | الأدوات المطلوبة |
   |:--|:--|
   | React، Next.js، Vite، Express، NestJS، React Native، Expo | `node` + مدير الحزم المستخدم (`npm` أو `pnpm` أو `yarn` حسب ملف القفل) |
   | Flutter | `flutter` + `dart` |
   | Django، FastAPI، Flask | `python` |
   | Firebase (المحاكيات والنشر) | `firebase` (Firebase CLI) + `java` بالإصدار **21 أو أحدث** للمحاكيات (الأقدم يرفضه Firebase CLI) — التثبيت: https://adoptium.net |
   | Flutter + Firebase | `flutterfire` (FlutterFire CLI) |

   الأدوات التي لا يفحصها السكربت (مثل Docker أو Android Studio) افحصها منفردة، مثل: `docker --version`.
3. استخرج الحد الأدنى للإصدار المطلوب من التوثيق الرسمي عبر WebSearch أو WebFetch (البند 4)، لا من الذاكرة.
4. اعرض جدول `| الأداة | مطلوبة لأجل | الحد الأدنى | المثبت | الحالة |` بالحالات: `✅ متوافق`، `⚠️ أقدم من المطلوب`، `❌ غير مثبت`.
5. المعالجة (البند 10):
   * `⚠️ أقدم من المطلوب` ← ابحث أولاً عن إصدار من المكتبة أو الإطار يعمل مع الأداة المثبتة واقترحه. إذا تغيّر الـ Stack بسبب ذلك فوثّقه في `decisions_log.md`. لا تطلب الترقية إلا إذا استحال البديل: اشرح السبب واطلب موافقة صريحة بخيارين مرقّمين في آخر الرد، لا بنافذة الأسئلة التي تغطي الشرح (`CLAUDE.md` §3): `1. **موافق على الترقية**`، `2. **ابحث عن بديل**`.
   * `❌ غير مثبت` ومطلوب ← وضّح أنه ضروري لتشغيل المشروع، وأعطِ رابط التثبيت الرسمي، وانتظر تأكيد المستخدم.
   * لا تنفّذ أوامر تثبيت أو ترقية بنفسك.
6. المنافذ: إذا كان منفذ مشغول 🔴 هو المنفذ الافتراضي للـ Stack (3000 لـ Next.js و Express، 5173 لـ Vite، 8081 لـ Metro و Expo، 8000 لـ Django و FastAPI، 4000 لواجهة محاكيات Firebase، 8080 لمحاكي Firestore، 9099 للمصادقة، 5001 لـ Functions، 9199 لـ Storage) فاقترح منفذاً بديلاً متاحاً 🟢، وأضف في القسم 6 سطراً قبل `* **البيئة النشطة محلياً:**`: `* **المنفذ البديل المعتمد:** <المنفذ> بدلاً من <المشغول>`.

## الخطوة 5 — Git Bash على Windows

تنطبق على Windows فقط؛ على macOS و Linux تخطَّها.

* &rlm;**Git Bash مكتشف** (سطر `* **الطرفية (Shell):**` في المخرجات يحتوي على `Git Bash ✅`): اكتب سطراً واحداً: `✅ Git Bash مكتشف — الـ Hooks وشريط الحالة تعمل.`
* **غير مكتشف، أو أداة Bash غير متاحة في هذه الجلسة:** اشرح بجدول:

  | ما يتوقف عن العمل | أثره عليك |
  |:--|:--|
  | Hook بداية الجلسة | لا يُحقن ملخص حالة المشروع تلقائياً |
  | نقطة التفتيش كل 15 رسالة | لا تذكير تلقائي بإعادة تثبيت السياق |
  | حارس الأسرار | لا حماية آلية لملفات `.env` ولا منع لكتابة المفاتيح السرية |
  | تذكير التوثيق وتنبيهات سقف الملفات | لا فرض آلي للتوثيق ولا لحجم الملفات |
  | شريط الحالة | لا يظهر اسم النداء والوضع والمرحلة أسفل صندوق الكتابة |

  الحل: ثبّت Git for Windows من https://git-scm.com/download/win بالخيارات الافتراضية، ثم أغلق Claude Code تماماً وأعد فتح **المجلد الجذري** للمشروع، ثم أعد تشغيل `/env-audit`.

## الخطوة 6 — التوثيق

1. **المشروع لم يُطلق بعد** (اسم المشروع يبدأ بـ `[`): حدّث القسم 6 فقط دون صف في `changelog.md`، واقترح `/kickoff`. الختم:

   `📋 التوثيق: ⬜ changelog (قبل الإقلاع) | ✅ project_map | ⬜ bugs_log (لا أخطاء) | ⬜ decisions_log (لا قرارات جديدة)`

2. **تغيّر القسم 6:** احصل على الوقت بالأمر `date "+%Y-%m-%d %H:%M"` ومرجع Git بالأمر `git branch --show-current` (أو `local` إذا لم يكن المجلد مستودع Git)، وأضف مباشرةً بعد آخر صف في `## جدول التغييرات`، دون سطر فارغ، صفاً بإصدار يزيد رقم PATCH لآخر إصدار:

   `| <التاريخ والوقت> | <الإصدار> | docs | Senior Project Manager | project_map.md, changelog.md | docs(env): تحديث نتائج الفحص البيئي — <أبرز تغيير> | <مرجع Git> | - |`

   الختم:

   `📋 التوثيق: ✅ changelog | ✅ project_map | ⬜ bugs_log (لا أخطاء) | ⬜ decisions_log (لا قرارات جديدة)`

3. **لم يتغير شيء:** لا تعدّل أي ملف. الختم:

   `📋 التوثيق: ⬜ changelog (لا تغيير) | ⬜ project_map (لا تغيير) | ⬜ bugs_log (لا أخطاء) | ⬜ decisions_log (لا قرارات جديدة)`

إذا سُجّل قرار في `decisions_log.md` (الخطوة 4) فاجعل خانته في الختم `✅ decisions_log`.
